**What was implemented**

- **CRUD with ownership semantics** — `createInstance` copies the request DTO, sets `status="CREATED"`, `ownerId` from the current user, and both timestamps, then `insert` (generated key written back by the retained XML). `getInstance`/`updateInstance`/`deleteInstance` all authorize through one path: admins reach everything, non-admins get `null`/`"NOT_FOUND"` for records they don't own — indistinguishable from missing. `listInstances` delegates to `findByFilters(ownerId, dbType, groupId, isAdmin)`. `updateInstance` applies only non-null request fields (never `dbType`/`status`/`ownerId`), stamps `updatedAt`, and persists.
- **Ping dispatch on stored `dbType`** — `MYSQL`/`REDIS` open a TCP socket to host:port with a 5000 ms connect timeout (`主机或端口为空` when host/port missing, `连接成功` on connect, `连接超时` on failure). `OSS` issues an HTTP GET from the service JVM itself via `HttpURLConnection` (connect + read timeouts of 5000 ms) to `http(s)://<host>/<schemaName>` with null schema treated as empty; any HTTP status yields `连接成功，状态码: <n>` with `reachable=true` and elapsed `latencyMs`, failures yield `连接超时`. Any other type (including null) makes no attempt and returns `不支持的实例类型`. Ping performs no persistence.
