Done. The single `<MASKED>` region in `src/main/java/com/docflow/platform/service/ImportService.java` is replaced with the `importZip` implementation plus a private `markFailed` helper, and `mvn package -DskipTests` builds `target/docflow-platform-1.0.0.jar` cleanly.

How the implementation maps to the contract:

- **Signature/state**: `public ImportTask importZip(Long workspaceId, String zipContentBase64, String zipFilename, String username) throws IOException` on the retained `@Service` class. It resolves the uploader via `userMapper.findByUsername`, inserts the `import_tasks` row first (`docCount` 0, `PROCESSING`, `createdAt` now), so failed imports still leave a queryable row.
- **Pipeline**: creates `{tmpDir}/{UUID}`, decodes standard-alphabet Base64, extracts every entry under the upload dir (directories via `createDirectories`, files via `Files.copy` with parents created), then picks the document root as the first subdirectory directly inside the upload dir (else the upload dir itself).
- **Selection/storage**: recursively walks the document root, keeps regular files whose names end `.html`/`.md`/`.txt` (via the retained `getContentType`), copies each into `{docsDir}/{workspaceId}/{relativePath}` with `REPLACE_EXISTING`, and inserts a `documents` row with `title` = file name, `filePath` = path relative to the document root, `fileSize` = stored copy size, `contentType`, `importTaskId`, `uploaderId`, `createdAt` now. This matches `DocumentService`'s read path `Paths.get(docsDir, workspaceId, filePath)`.
- **Finalization/errors**: on success sets final `docCount`, `COMPLETED`, `completedAt` now, updates the row, and returns the task. Classified failures (undecodable Base64, `ZipException`/format error, zero entries) call `markFailed` (row → `FAILED` with `completedAt` now) before throwing `IllegalArgumentException`; any other exception propagates with the row left `PROCESSING`. The upload dir is deleted in a `finally` on every path after creation.

One judgment call: a ZIP entry whose resolved path escapes the upload dir (zip-slip) is treated as a format error — `FAILED` + `IllegalArgumentException` — since the contract classifies format errors that way; normal archives are unaffected.
